# Game Previews and the Post (r91, migration 206)

**Canonical split: FEED = PREDICT, POST = GAME PREVIEW + CONVERSATION.** The feed owns every prediction (Moneyline, Total, Spread, Confidence, commitment, sentiment, locked state). The opened Post carries what the feed does not: the Game, how the crowd picked on each Market, a short editorial **Game Preview**, the one shared conversation, and Other Picks / Call BS. It is not a second prediction surface: no Pick buttons, no Confidence control, no "more markets" links. (The Market page `/markets/[id]` keeps its full card; nothing links to it from the Post any more.)

## Feed
Every Game card has an explicit, always-visible text link **Game Preview** (accent colour + chevron, never icon-only, never hover-only) beside the matchup title (below it on a phone, where the title takes the row), `data-slot="game-preview-link"`, accessible name "Open game preview for {away} at {home}". It links to the canonical Post — there is no second Preview page. The matchup title stays a secondary path to the same place. The link needs only the Post id the card already has: the feed fetches no Preview text. It is present for any Game with a Post, whether or not a Preview has been written yet.

## Post
Order: Game identity → Market sentiment (Moneyline, Total, Spread in the configured template order) → Game Preview (hook, story) → Sponsor promotion (if any) → Conversation → Other Picks / Call BS. A Game with no saved Preview simply has no Preview block (no placeholder, no error).

**Sentiment** (`lib/posts/game-sentiment.ts`, `components/posts/GameMarketSentiment.tsx`) obeys the product's commit-before-crowd rule per Market: percentages and the predicted count appear only once the viewer's own prediction on THAT Market is final; before that the block says "Make your pick in the feed to see how everyone else picked." One Pick is one vote (Confidence never weights it), the numbers are the canonical Pick aggregate, a Market nobody has picked says "No one has predicted yet" (never 0% / 0%), and a single Pick is a real 100% / 0%. Labels are the shared team-native choice labels (NHL stays canonical SPREAD with puck-line wording). Each block also carries the viewer's own prediction as context ("Your prediction: Washington Capitals · 🔥5 · Result: Correct") — a line, not a card. One batched read however many Markets the Game has.

## Storage (migration 206)
| Table | Purpose |
|---|---|
| `game_preview_config` | one row: `max_chars` (700), `hook_max_chars` (120), `lead_hours` (48), `stale_after_hours` (36), `min_refresh_interval_hours` (6). Nothing is hard-coded in code; changed by a Super Admin (audited `settings.game_preview_updated`) at **Admin → Game Previews**. |
| `game_previews` | the CURRENT Preview of a Game (unique per fixture): hook, body, `status` PUBLISHED/WITHDRAWN, `generated_by`, `generated_at`, `checked_at`, `refresh_count`, `frozen_at`. |
| `game_preview_sources` | provenance: URL, provider, title, `published_at`, `retrieved_at`, `supports` — required and validated; not shown to Members. |
| `game_preview_revisions` | every Preview a refresh replaced (text, sources, why). |

No Member or anonymous role can read or write any of them (RLS, no policy, no grants); the Post reads through the server.

## Writing — one validated function
`upsert_game_preview(fixture, hook, body, generated_by, reason, sources, claims, meta)` (service role only; `saveGamePreview` in `lib/game-previews/repository.ts`). It refuses: text that is empty or longer than the configured limits (nothing is padded or cut); a Preview without complete provenance (1–12 sources, each an http(s) URL + provider + title + a retrieval time that is not in the future); a Game that has started (`game_started` — the pregame Preview is frozen at kickoff and never rewritten); an unknown reason. Reasons: `MISSING` (create; or recreate after a withdrawal), `STALE` (only when `checked_at` is older than `stale_after_hours`), `MATERIAL_NEW_INFORMATION` (only when the Preview is older than `min_refresh_interval_hours`), `MANUAL_ADMIN_REQUEST` (always, before kickoff). A refresh keeps the replaced version in `game_preview_revisions`. Concurrent writers are serialized per Game by an advisory lock (exactly one `created`).

## When and by whom
**Never at render time.** Pipeline: Game scheduled → (background) research → Preview written and verified → saved through `upsert_game_preview` → the Post reads the saved row. `game_preview_candidates()` lists published, unstarted Games starting within `lead_hours` that have no Preview (or a withdrawn one) or whose last check is older than `stale_after_hours`. The existing housekeeping job (`/api/cron/prune-provider-request-log`, no new scheduler entry) runs `runGamePreviewHousekeeping`: it **freezes** the Preview of every Game that has started and reports how many Games still need one (`gamePreviews: { frozen, missing, stale }` in the job result). It writes no editorial text: the research-and-writing step is a separate producer that calls `saveGamePreview`.

## Factual standard
Every claim must come from verified material tied to that specific Game (recent results, a player streak, an injury or return, a milestone, head-to-head history, a record chase, an unusual statistic). If there is no strong angle, a simpler verified factual preview is correct. The style references in the product spec are tone only; their facts are never reused for another Game. Each Preview is stored with its sources and when they were retrieved, so an operator can audit it.

## Operator tools (Admin → Game Previews, Super Admin)
Limits and timings; the next 14 days of published Games with their status (needs a Preview / saved / stale / withdrawn); each saved Preview with its generator, timestamps, refresh count and a collapsible source list; and **Withdraw** (requires a reason; audited as `game_preview.withdrawn`; hides it from the Post immediately; text and sources stay on record; a new Preview can then be written).

## Automated generation (r92 migration 207, r95 migration 208)

**The editorial goal:** find the most interesting TRUE story around this specific matchup, then use only the facts that story needs. A Game Preview is a story hook, not a miniature game-notes page. Records, standings and last-game scores are fallback context, rarely the story itself.

**Provider-neutral contracts** (`lib/game-previews/providers/types.ts`): `GamePreviewResearchProvider`, `GamePreviewAngleProvider`, `GamePreviewWriterProvider`, optional `GamePreviewVerifierProvider`. The Game / Post domain and the pipeline depend only on these; nothing outside `providers/` knows a vendor's request or response shape. `providers/index.ts` selects the implementation named by the stored `provider`. **V1 = Anthropic** (`providers/anthropic.ts`, official `@anthropic-ai/sdk`, Messages API): research uses Anthropic's **server-side web search tool**; angle selection, writing and the optional read use the configured model with `output_config.effort`. Sampling parameters are left at defaults and `thinking` is not overridden (current models manage it). A new vendor is a new implementation + one registry case + a migration widening the `provider` check. (An earlier OpenAI implementation was removed rather than kept untested.)

**Configuration, not constants** (`game_preview_config`, edited at Admin → Game Previews, audited): provider, **model** (no default anywhere; no silent fallback to another model — an unavailable model fails the run with the API's own error), **effort** (default `medium`), **web-search tool version** (the API versions its server tools; default `web_search_20250305`, selectable `web_search_20260209` / `web_search_20260318` so a rejected version is a setting change, not a deploy), web search on/off (off = no generation), automatic generation (**OFF**), verification on/off, **searches per Game (default 3)**, attempts, Games per scheduled run, lead time, stale window, minimum refresh interval, length limits, how many facts one Preview may cite (default 4), the minimum story score (default 3), how recent a "current" source must be, preferred/blocked source domains. The **API key is never a setting**: `ANTHROPIC_API_KEY` comes from the environment (optional `ANTHROPIC_BASE_URL`); the admin page shows only whether it is configured; errors and logs never carry it.

**Pipeline** (`pipeline.ts`, every dependency injected): eligible Game → **research** (mandatory web search; structured candidate facts: claim, kind current/historical, category, supporting excerpt, source URL/provider/title, publication time, retrieval time, relevance, game association; a fact is kept ONLY if its source is a page the search actually reached, and never from a blocked domain; every reached page is recorded as accepted or rejected with why) → **3-5 candidate editorial angles** (types HOT_VS_COLD, STREAK_ON_THE_LINE, PLAYER_ON_FIRE, REVENGE, RECORD_CHASE, HISTORICAL_ODDITY, COMEBACK, COLLAPSE, BREAKOUT_PLAYER, INJURY_RETURN, OLD_TEAM_NEW_TEAM, DOMINANCE, UPSET_THREAT, CONTRAST, UNFINISHED_BUSINESS, RIVALRY, WEIRD_STAT, MILESTONE, plus the SEASON_RECORD fallback — internal labels, never shown), each **scored 1-5** on tension, surprise, specificity, human interest, conversation potential, recency, with the facts it needs → the strongest story is chosen; **a records-only choice is overridden by any real story scoring at least the configured minimum** → the **writer is given only the chosen story and only its facts** and tells that one story → **deterministic provenance validation** (length limits; every claim cites researched facts; no blocked source; current-state claims inside the freshness window; every figure — digits, spelled numbers, ordinals — present in the cited facts; names a team of this Game) → **deterministic editorial validation** (`editorial.ts`: cites only the chosen story's facts and no more than the cap; the hook does not merely state a record or score and is not made of figures; not a statistics dump; no generic filler such as "both teams are looking for a win"; no sportsbook language; no stock closing question; the preview is not the hook repeated) → optional **model read** (supported by its facts AND editorially passes: would the hook stop the scroll, is it specific to this matchup, one story, reads like an editor) → saved with provenance. Every rejection reason is fed back to the writer for a rewrite, up to the configured attempts; when all fail **nothing is saved** and the Post is untouched. The deterministic checks are authoritative; the model read is supplemental and only runs once they pass. Weak research never becomes a manufactured story (`no_verified_facts`).

**Stored decision record.** The Preview keeps the claim → fact → source map (`claims`), the cited facts, provider/model/effort/search tool version/prompt version, the chosen angle and every candidate angle with its score (`generation_meta`). Each run (`game_preview_runs`, with `details`) keeps what it found and decided: sources reached / used / not used (and why), the facts, all candidate angles with scores, which was selected and which chosen (and whether overridden), the rejected angles, and every attempt's hook, preview and rejection reasons — shown in Admin → Game Previews under "What it found and decided".

**Freshness.** `current` is only for what can change before the game (injury, return, availability, expected starter); results, scores, records, streaks and history that follow from completed games are `historical` and are stated as what happened. **A `current` fact whose source has no publication time (or is older than `current_fact_max_age_hours`) is set aside before the angle stage** (`splitUsableFacts`): it is recorded in the run with the reason but never reaches the angle or the writer, so a story is never built on a fact the provenance gate would reject. If nothing usable is left the run is REJECTED (`no_usable_facts`). The chosen story line may not name a figure its facts do not hold: the pool fact that holds it is added to the story (`completeAngleFacts`, recorded as `angleFactsAdded`). The matchup itself (who plays whom, where, today) is given to the writer and is not a claim.

**Story-first research and verification (r104).** Research runs in stages (the system prompt, `providers/anthropic.ts`): resolve the canonical Game first; search for STORIES before statistics (previews, each team's latest news, injuries, player names discovered); then matchup history only to support a story; follow an interesting lead with a targeted search; stop early (the search limit is a ceiling, 6 for the pilot, not a target). Research returns `leads` (what it noticed, tied to facts) and `conflicts` (sources that disagree — the safe agreed statement is used, never the more dramatic number); both are recorded in the run and the leads reach the angle stage as hints. Candidate angles must be genuinely different: `dedupeAngles` keeps the stronger of two angles on the same facts or of the same kind and records the dropped one (`angleDuplicatesDropped`) — it never rejects the run (a Game whose news is mostly injuries gets two injury stories; rejecting for that cost two of the first four runs on the trusted-source pipeline). **After the story is chosen and before anything is written, every fact it needs is independently verified** (`verifyFacts`, gated by `verify_with_model`, searches limited to what is left under the ceiling): the source supports the exact claim, season and team are right, no authoritative source disagrees. Only `confirmed` counts. A fact that fails removes its story (the next-best story whose facts stand is checked); if none stands the run is REJECTED (`story_not_verified`) and the writer is never called. The writer only ever sees verified facts. **Stale news and history-only stories (r108).** Found by the owner on the first calibrated Celtics @ Pistons Preview: its credited source was ESPN, Mar 6, 2026 (last season), the story was Tatum's last-season comeback, and its forward-looking lines ("a full season in front of him") rested on no current fact; the reviewer had filed that as advisory. Causes and fixes: (1) a story's credited primary source is chosen among ITS OWN facts (`orderAnglePrimary`): eligible (trusted, not a betting page) and, when the story rests on this season at all, a CURRENT-SEASON fact — so a first-listed untrusted fact no longer drops a good current story (the Paul George debut) and no last-season article is credited for a current story; (2) a report published before the current season began (`currentSeasonStart`: NFL/NBA/NHL; Jul 1 for an Aug–Dec Game, Aug 1 of the previous year for Jan–Jun) is last season's news and is re-scoped to history; (3) a story that rests ONLY on earlier-season facts is reviewed with extra BLOCKING rules (nothing about the present or future without a current fact; it must be tied to THIS matchup, or it is a misleading implication), and every story is reviewed for present/future claims no cited fact states; (4) research output is compact (at most 14 facts, short excerpts) with more token headroom (one run was lost to a cut-off answer).

**Quality-gate calibration (r107): reject wrong stories, not imperfect prose.** Findings are classified. **BLOCKING** = the Preview is wrong or misleading: unsupported claim (incl. an attributed motive), wrong figure/entity/season/game, stale current-state fact, a source conflict that matters, a logical contradiction, an unsupported causal link or misleading implication (true facts misused — a defender's injury presented as burdening the offense), a fabricated quote, betting language; deterministic blockers are facts outside the story, the primary fact not cited, "this season" on earlier-season facts, an ambiguous postseason year, a time of day, sportsbook words, unsupported figures. **ADVISORY** = taste: bland story, weak hook, game-note feel, repetitive structure, low conversation, wording, a hook that states a record, a stat dump, generic phrasing, a stock closing question. The independent read (`verify`) returns the two lists separately (category and kind enums); advisory findings NEVER reject. A factually valid draft with advisory notes gets **at most ONE polish rewrite** (the writer is told the draft is sound and the facts must not change); the rewrite is saved if it is also valid, otherwise the earlier valid draft is saved (`advisoryRewrite`: `none` / `kept_rewrite` / `kept_original`); no attempt left means the valid draft is saved as is. Advisory notes and blocking counts (rule vs reviewer, by category) are recorded in the run and the Preview's `generation_meta` for pilot analysis. **Figures** (`claimedFigures`): digits always count; spelled numbers only in a quantitative context ("five straight", "two touchdowns", "ranked third"); ordinals only for factual claims ("first in the league", "their first win of the season", "fourth road game") — "his first chance", "the first meeting", "two stars are out", "the first to arrive" are prose. **History** needs no label merely because it happened before today; only a genuinely ambiguous or misleading season blocks (the reader judges; "currently"/"this season" on earlier-season facts and a bare "2026 playoffs" still block). The **hook limit** is the stored `hook_max_chars` (20-300), not a constant. **Betting/odds/picks pages** (`isBettingPage`, by URL or title) are never the credited primary source even on a trusted domain, are never listed in the public credit, and a fact from one is an exception that must be verified; a Preview whose recorded primary source is a betting page is not shown.

**Trusted-source pipeline (r105, owner's simple pipeline).** Game -> trusted-source search -> strongest story -> sanity-check -> write -> basic validation -> save with provenance -> visible source credit. **One trusted source is normally enough**: the story must rest on a *trusted primary source* (the first fact of the angle; trusted = the stored `preferred_domains` list or a team's own site; a blog, farm or aggregator is never primary, `isTrustedSource`), and a fact from a trusted source that clearly says what is claimed is NOT re-verified. Only **exceptions** are verified (`verificationReasons`): a source outside the trusted group, research's flags (ambiguous season/date/team, unusually surprising, trusted sources disagree), no passage showing the source says it, a current-season figure on a page that cannot place it. Exceptions go through the evidence-first check below (stored evidence first, then one targeted search); without a verifier an exception rejects the story. Basic validation adds: the draft must cite the story's primary fact, no quote that is not in a cited passage, no time of day, no betting language, no unsupported figure, no season ambiguity, hook/preview length. **Public attribution**: every published Preview credits its primary source in small secondary print under the text ("Source: ESPN · Oct 15, 2026", linking to the publisher's own page in a new tab; `GamePreviewSection`), plus "Also: ..." only when the story materially depends on a trusted source from a different publisher (at most two, never a bibliography). The stored sources are primary-first; `generation_meta.publicSourceUrls` records which are public (`derivePublicSources`); a Preview with nothing to credit is not shown (the database already refuses a Preview with no sources). Research sees recent hooks so structures vary (no "Three games. Four goals. Boston, you're next.").

**Verification is evidence-first (r105).** Research captures, per fact, the passage WITH its surrounding context, the kind of page (`stats_page`, `standings`, `game_log`, `schedule_results`, `recap`, `article`, `injury_report`, `profile`, `archive`, ...), what the page IS (`pageContext`), the season the page itself identifies (`pageSeason`) and the team of any person named (`subjectTeam`). `verifyFacts` then runs in two steps: (1) judge every fact the chosen story needs from that stored evidence, with no search — a current-season stats/standings/game-log/schedule page from a major provider places a figure in the current season through its identity even if the visible row omits the season, while an undated biography, archive or historical page cannot; (2) only for facts the evidence could not settle, one targeted search for the exact unresolved claim, within the searches left. A fact the evidence contradicts is `disputed` without a search. A page that cannot be retrieved during verification is recorded (`retrievalFailed`), not treated as a false claim; if neither the stored evidence nor targeted corroboration establishes a fact it is not confirmed and the run is rejected. Each run records a `measurement` (research vs verification searches, facts discovered/selected, confirmed from stored evidence vs after a targeted search, disputed, unsupported, retrieval failures) so the sufficiency of the six-search ceiling can be judged from data after the pilot sample. The 1/3 reserve below is a safety net, not a requirement to spend it.

**The search ceiling covers research AND the fact check**: when facts are verified a third of the ceiling (rounded down, 2 of 6) is held back from research (`verificationReserve`), and unused research searches roll over to the check. Without the reserve a research pass that used every search left the check to judge from excerpts alone (first three runs on the new pipeline: all `story_not_verified` for "could not retrieve the page").

**Current season vs historical context.** Every fact carries a `seasonScope`: `CURRENT_SEASON` (this season's record, standing, streak, form, injury, availability, trends, milestones and meetings) or `HISTORICAL_CONTEXT` (earlier seasons and long-run frames: head-to-head and rivalry history, prior playoff meetings, franchise records, "first time since"). Research classifies; an unlabeled fact defaults to history, and a deterministic backstop (`reconcileSeasonScope`) moves a fact whose own wording names an earlier season ("in 2025", "last season") to history — it only ever demotes, and a current-state fact is always this season's. Each candidate angle gets a computed basis (`CURRENT_SEASON`, `CURRENT_WITH_HISTORY`, `HISTORY_ONLY`; recorded in the run as `angleBasis`). Editorial priority is enforced in `chooseAngle`: a records-only or history-only choice is set aside when any story with a current-season core clears `min_story_score`; history carries the Game only when the season offers nothing that clears the bar. Draft validation requires every claim that rests only on earlier-season facts to be explicitly framed as history (a year, "last season", "the last time", ...) and rejects one worded as this season's; the model read also flags statements that blur seasons. **A time frame is a claim too:** "this season" / "this year" in a claim, the hook or the preview is rejected unless a cited fact itself says so (a streak of "six straight games" may reach into last season). Found by the first real generation's manual fact-check (r99). **A league rank or lead is a current-state fact** however research filed it (`reconcileFactKind`: "tied for the most in the NFL", "ranks 29th", "last unbeaten team" are re-filed as `current`), so it needs a dated source inside the freshness window; found when a sample Preview's "tied for the most" went stale after Thursday's game (r100). A Preview may name a team by full name, nickname or city, and may not state a time of day ("tonight").

**When it runs.** Never when a Member opens a Post. The scheduled housekeeping job calls `runGamePreviewAutomation`: a no-op (and no external call) unless `generation_enabled` is on, a model is set and `ANTHROPIC_API_KEY` exists; then at most `max_games_per_run` of the soonest Games needing a Preview. An admin can always **Generate now / Regenerate** one Game explicitly. Refresh rules and the freeze at kickoff are enforced by the database.

**Operations.** Every attempt is recorded (trigger, reason, status SUCCEEDED/FAILED/REJECTED, provider, model, effort, tool version, attempts, web searches, model calls, tokens, facts found, error, details). Admin → Game Previews shows the summary (Games researched, Previews, failures and rejections, regenerations, searches, model calls, calls per Preview, tokens, provider/model) and the latest runs. Nothing about cost is shown to Members.

**Manual control.** A Super Admin can inspect a Preview and each claim's sources, regenerate, **edit** the text by hand (a note is required; the stored sources stay; the old version is kept; audited; refused after kickoff), or **withdraw** it (reason required, audited).

**Editorial examples.** The writer prompt carries tone examples (never to be reused as facts) and the principle that a better Preview comes from story selection, not invented facts: "Houston has its first win. Jacksonville has three straight." reads like game notes; the same facts built around one tension ("Houston finally won. Jacksonville wants to make it a one-week story.") do not.

## Pipeline reset (r109): the canonical editorial contract
The audit that preceded this change is `game-previews-reset-audit.md` (every reject rule classified A-E). Where this section disagrees with an earlier paragraph above, this section wins.

- **Contract inputs.** Game ID, league, away/home, scheduled start with the venue timezone, the **season identifier** the platform stores (`fixtures.season`) and the **competition phase** (`identity.ts competitionPhase`, from `fixtures.round`: preseason / regular season / playoffs). The season is never inferred from the calendar year. Research confirms the Game against an official source and returns `game_check`; a mismatch ends the run as `needs_review: game_mismatch` with the specific conflict (the Game is never silently swapped).
- **Currentness is the primary gate**, decided by the research/story/writer/reviewer prompts (one contract text shared by every stage in `providers/anthropic.ts`): previous-season material is `HISTORICAL_CONTEXT`; it may be primary only when fresh reporting revives it or it is directly central to the matchup; opening-week context (preseason, camp, offseason, current injuries) counts as current. Code keeps only one deterministic backstop: a "current-season" fact published before the season start derived from the supplied season identifier is demoted to history. No calendar-year regexes remain.
- **Stale or undated current-state facts are exceptions, not exclusions** (`verificationReasons` with a freshness context): the story that rests on one must verify (evidence first, then one targeted search) or it is not used.
- **Deterministic validation = deterministic facts only** (`validateDraft`): title and caption present; title + caption combined fewer than `max_chars` (exact count, configurable, default 700); at least one claim, each citing known facts; no fact from a blocked domain; no quote absent from a cited passage; the contract's style invariants (no em dash, hashtag, wagering terms, "epic showdown", "must-watch clash", "both teams want the win"). There is **no separate title-length gate** (`hook_max_chars` remains only because the database still checks the column; keep it at 300). Figures and "this season" wording are computed as **hints** (`draftHints`) and handed to the reviewer; they never reject.
- **Reviewer** (semantics): BLOCKING = unsupported claim, wrong figure/entity/season/phase/game, stale-as-current, source conflict, `not_relevant_now`, logical contradiction, unsupported causation, misleading implication, fabricated quote, betting language. ADVISORY (never rejects, at most one polish rewrite) = bland, weak title, game-note feel, repetitive structure, low conversation, wording.
- **Writer output** = the contract shape (`status` ready | needs_review, `reason`, `title`, `caption`, claims with `evidence`). `needs_review` ends the run with the reason; nothing is saved.
- **Provenance** adds per-claim `evidence`, `season`, `phase`, `researchedAt` to the stored claims/meta (no migration: `claims` and `generation_meta` are jsonb). The public footer links only to a readable story page (`isStoryPage` rejects JSON/API endpoints) and never to a betting page; at most one primary + one secondary; a missing date is shown as no date.
- **Candidate stories** are cleaned structurally (`sanitizeAngles`): no required count of 3-5; only "nothing usable" rejects.
- **Unchanged and configurable:** search ceiling (default 6, a ceiling), max attempts 3, model, provider, trusted/blocked domains, length limit, enablement; automation stays OFF; no request-time generation.
- **Admin:** Admin → Game Previews lists published Previews of already-started Games with a Withdraw form (reason required, audited).

## Final hardening (r111): defects found by the reset pilot
- **Evidence eligibility is not public-credit eligibility.** Any non-blocked source can be evidence for a fact. The PUBLIC primary must be trusted AND creditable (`isCreditablePage`): a readable page, not a data endpoint/JSON feed, not a PDF or uploaded document, not a live list/table page (injuries, schedule(s), scoreboard, standings, stats, roster, depth chart, transactions, game log: decided on whole URL path segments), not a betting page.
- **The public primary supports the central story.** The angle stage returns `central_fact_ids` (the one or two facts that establish the story). The public primary is chosen among them (`orderAnglePrimary`); a story whose central claim has no trusted, creditable source is not publishable. The reviewer also sees the central story and the credited source and blocks `central_source_mismatch`. The run record keeps `centralStory` (primary claims, primary source, secondary).
- **Secondary source** (at most one) only when a trusted, readable source from a different publisher supports a claim the primary does not. A source that was merely consulted is never shown.
- **Status certainty is blocking** (`status_overstated`): "unlikely to play" is not "out", "questionable" is not "will play", "expected to return" is not "returns", "projected starter" is not "starter", "could play" is not "will play", especially in the title. Code passes the hedges found in the cited facts to the reviewer as hints.
- **Drop a bad fact, not automatically the story.** A fact that fails verification (disputed, unsupported, stale, ambiguous) is removed from its story. The story is kept when its central facts stand and still have a creditable trusted source; otherwise that story collapses and the next-best supported story is prepared from the research already gathered (no new research cycle), before the Game is returned as `needs_review`. A writer decline also moves to the next-best story. All inside the same attempt budget (max attempts unchanged). `factsRemoved` and `storyAttempts` are recorded in the run details.
- **Betting detection** is by page purpose: "preview", "prediction(s)" and "picks" alone are not betting; they count only with a wagering term (odds, spread, line(s), bet(s), props, parlay, sportsbook, moneyline) or inside a betting section (/betting/, /odds/, /sportsbook/, /picks/ hub).
- **Source dates.** A credited source whose date research did not capture is read from the page's own structured metadata (JSON-LD `datePublished`, `article:published_time` and similar; never modified/updated times, URLs or retrieval time) by `source-dates.ts`; if the page states none the date stays null.
- **Timezone.** See `venue-timezone-audit.md`.
- **Trusted-domain list unchanged.** Whether to trust Yahoo-hosted syndications is an open owner decision (see the final hardening report).

- **Credit lookup (r112).** The first re-test showed that a story's central claim often first appears in a lower-trust or republishing source (Yahoo syndications, fan sites, a regional paper's syndication) while a trusted page carries the same reporting. When a story is otherwise supported but its central claim has no trusted, readable source, one search restricted to the stored trusted domains (`web_search` `allowed_domains`) looks for that page (`findTrustedSources`, only when the search ceiling has room). A trusted, readable, reached page that states the claim becomes the central fact and the public credit; the lower-trust page stays valid evidence. Nothing found means that story cannot be credited and the next-best story is tried. A comparably strong story that is already creditable is preferred to one that needs a lookup. The trusted-domain list itself is unchanged.
- **Team websites and certainty (r113).** An official team website is recognised by its whole domain label (`teamSiteLabels`: nickname, "the"+nickname, city+nickname, city initials+nickname, two-word nicknames), not only the bare nickname: `therams.com`, `detroitlions.com` and `nygiants.com` are team sites; a substring match is not ("cheat.com" is not the Heat's). Certainty inflation is blocking beyond player status: a hedged announcement ("I'm pretty sure this is my last year") written as settled, and a statistic given "so far" or as of an earlier game presented as the current number (`stale_current`). The hedge hints also cover "pretty sure", "so far" and "as of".

## Release gate (r116): current-number freshness, Yahoo policy, secondary materiality, Admin attribution
- **Current-number freshness.** Research classifies every figure: `CURRENT_STATE` (season record, average, total, rank, streak, "so far", "already has"), `FIXED` (a specific completed game, last season, "entering the season", a founding year) or `NONE`, with the date the figure is current through (`as_of`, its own words in `as_of_label`). The loader supplies the latest COMPLETED Game of each team before the fixture (`GameIdentity.lastCompleted`, from `fixtures.internal_status = COMPLETED`). `staleNumberCandidates` (deterministic) flags a `CURRENT_STATE` number whose evidence date (its as-of date, else the page date; a date with no time covers its whole day) predates a relevant completed Game (the fact's own team, else either team); no evidence date is also a candidate; an opener has none; `FIXED` numbers are never flagged and the wording ("so far") is never trusted. A candidate is NOT false: it is refreshed (`refreshNumbers`: official league/team stats first, then another trusted current source) as confirmed, updated to the current value, or removed; a refreshed value that still predates the Game is removed. Removal follows the existing salvage rules (peripheral: story kept; central: next-best story). The reviewer receives the scope of every cited figure (`staleNumbers`, `fixedNumbers`) and keeps `stale_current` blocking: a true number from an older source can still be stale, and an entering-season figure must not be written as the current one. The cutoff is the supplied Game: only Games completed before it count.
- **Yahoo policy.** `yahoo.com`, `msn.com` and `aol.com` are syndication hosts (`publishers.ts`). Hosting there is never trust. A syndicated page is trusted ONLY if it identifies an original publisher (the original URL, or the name of a publisher Brohda knows, "Originally appeared on ...") and that publisher is already on the trusted list (`isTrustedFactSource`); otherwise it stays untrusted. Public identity is the original publisher, the evidence URL stays the page actually used, and the original publisher's own page is preferred for the public link when the approved credit lookup finds it. No trusted-source configuration changes.
- **Secondary credit** appears only if it backs a claim that is STATED in the public title or caption (`claimAppearsInText`); a claim kept only in the research metadata does not qualify. Internal provenance keeps every source.
- **Admin attribution (migration 209).** `game_preview_runs.actor_id` records the authenticated Super Admin behind an ADMIN run (from the server session, never the request); it is NULL for AUTOMATIC runs and for every run recorded earlier (unknown, never guessed). A DB check allows an actor only on ADMIN runs, and a trigger refuses a non-Super-Admin actor and writes the existing `audit_logs` event `game_preview.generate` (actor, Game, run, status, error, preview) in the same transaction.
- **Completed-games loader (r117).** The r116 freshness gate depends on `GameIdentity.lastCompleted`, which the loader did not populate (found by the controlled credit-lookup run: the prompts said "a season opener" and no number was ever flagged). `latestCompletedGames` (`completed-games.ts`) now reads each team's most recent COMPLETED earlier Game (same provider, competition and season identifier). Three states are distinct: games found; known none (an opener: nothing can be stale); UNKNOWN (the schedule data could not be read), where every current-state number is a stale candidate and the prompts say the completed Games are not available. The prompts never claim an opener unless the schedule data says there is none.
